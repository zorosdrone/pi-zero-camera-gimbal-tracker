# ベンチマーク結果

Raspberry Pi Zero 2 W実機で確認した結果です。モデル、入力解像度、前処理が異なるため、方式間の一般性能ではなく、この構成における判断材料として扱います。

| 方式 | 条件 | 実測結果 | 判断 |
|---|---|---|---|
| カメラ取得 | 640×480 main、320×240 lores | 約14.98fps | 実用範囲 |
| MJPEG配信 | 640×480 | 配信中CPU約12.4% | 実用範囲 |
| YOLOv5nu / OpenCV DNN | 640×640 | 保存画像約17秒、カメラ約0.052fps | リアルタイム追跡には不適 |
| MobileNet-SSD / OpenCV DNN | 300×300、4スレッド | 平均約4.85秒、約0.206fps | リアルタイム追跡には不適 |
| Edge Impulse FOMO | 64×64 | 推論約2〜3ms、ライブ処理約14.70fps | 速度は候補 |
| FOMO静止画13枚 | 人物あり7、人物なし6 | 画像単位7/13、背景誤検出が多い | 現モデルのまま追跡へ接続しない |
| KCF | ブラウザーでROIを手動選択 | 起動、ROI API、サーボ指令を確認 | 実映像評価を継続 |

## 現時点の判断

- Pi Zero 2 W上のOpenCV DNN方式は速度不足のため終了。
- FOMOは速度面で有望だが、実カメラ環境に合わせた再学習が必要。
- KCFは対象を人が選択するため、検出器の誤検出を切り離して追跡・ジンバル制御を検証できる。
- 完全自動追尾を名乗る段階ではない。
